# 开放接口：群聊消息推送接入指南

开放接口让**局域网里另一台电脑**上的程序（Telegram / Discord / QQ / Slack 机器人等）把群消息推进技术瓜群流。推进来的消息和微信群消息走同一条通路：本地页、gmgn 插入、浮窗、提示音、合约识别、CA 发现榜、喊单人战绩都照常工作。

- 协议版本：`v1`
- 方向：推送端 → 本服务（HTTP POST），本服务不会主动连推送端。图片和头像例外，见第 6 节。
- 鉴权：每个请求都用密钥做 HMAC-SHA256 签名，密钥本身不在网络上传输。

## 1. 开启

1. 打开本地页右上角「开放接口」（`http://127.0.0.1:8765/open`）。
2. 点「生成新密钥」，**马上复制**。密钥只显示这一次，形如 `wfo_` 加 43 位字符。之后页面只显示末 4 位，要换就重新生成，旧密钥立即失效。
3. 勾「开启开放接口」，确认监听地址和端口后保存。默认 `0.0.0.0:8766`，也可以填本机的某个局域网 IP，只在那张网卡上监听。
4. 页面顶部显示「监听中」，并列出推送地址，例如 `http://192.168.1.5:8766/open/v1/messages`。
5. 放行 Windows 防火墙。第一次监听时系统可能弹窗；如果没有弹窗、推送端又连不上，用**管理员** PowerShell 执行：

   ```powershell
   New-NetFirewallRule -DisplayName "wechat-feed open api" -Direction Inbound -Protocol TCP -LocalPort 8766 -Action Allow -Profile Private
   ```

   `-Profile Private` 表示只在「专用网络」下放行。如果你的局域网被 Windows 识别成「公用网络」，先在系统设置里改成专用网络，不要对公用网络开端口。

6. 在推送端运行示例脚本 `scripts/open_push_example.py`，选 `1` 测试连通和签名。返回 `ok: true` 就说明网络和签名都通了。

## 2. 安全模型

| 层 | 做法 |
| --- | --- |
| 端口隔离 | 局域网端口上**只有** `/open/v1/*`。本地页、`/api/*`（群消息、配置、Key）仍然只监听 `127.0.0.1:8765`，局域网访问不到。 |
| 来源 IP | 默认只接受私有网段（`10/8`、`172.16/12`、`192.168/16` 等）和本机。公网来源一律 403。可以在页面里填 IP 白名单收紧到具体机器，例如 `192.168.1.20`。 |
| 签名 | `HMAC-SHA256(密钥, 时间戳 + 方法 + 路径 + 请求体)`。改动请求体的任何一个字节，签名都会失效。 |
| 防重放 | 时间戳和服务器时间相差超过 ±300 秒的请求会被拒收；在这个窗口内重放，会因为消息 id 相同被当成重复消息。 |
| 防爆破 | 同一个 IP 一分钟内签名错 20 次，封禁 5 分钟。 |
| 限流 | 每个 IP 每秒最多 20 个请求、每分钟最多 1200 条消息，每个请求最多 100 条消息、512 KB。 |
| 浏览器 | 带 `Origin` 头的请求一律拒绝，网页里的脚本不能调用这个接口。 |
| 输入 | 字段按白名单校验，控制字符和双向文本控制符会被去掉，正文最多 2000 字。页面渲染时所有文本都会转义。 |
| 群范围 | 新群默认**不入库、不显示**。必须先在「开放接口」页或「群聊选择管理」里把群加入监控。 |
| 密钥保存 | 和 GMGN Key 一样，保存在本机 `data/settings.json`，`GET /api/settings` 不会返回密钥。打包脚本不会带上 `data/`。 |
| 微信库 | 推进来的群 ID 带平台前缀（例如 `telegram:-100123`），不会和微信群混在一起，也不能冒充微信群。 |

本服务和推送端之间是明文 HTTP。签名能防止密钥泄露和内容篡改，但消息内容本身在局域网里看得到。如果推送端要跨公网，请走 Tailscale / WireGuard 这类加密隧道，并把隧道网段写进 IP 白名单。不要做公网端口映射。

## 3. 签名

每个请求都要带这两个头：

| 头 | 值 |
| --- | --- |
| `X-WF-Timestamp` | 当前 Unix 时间，**秒**，十进制整数 |
| `X-WF-Signature` | 签名，小写十六进制 |

签名原文是下面几部分直接拼接成的**字节串**：

```
<时间戳>\n<大写方法>\n<路径>\n<原始请求体字节>
```

- 路径不含域名、端口和查询串，例如 `/open/v1/messages`。
- 请求体必须和实际发出去的**字节完全一致**。先把 JSON 序列化成字节，用这份字节签名，再把同一份字节作为请求体发出去。不要签一份、发的时候让 HTTP 库重新序列化一次。
- GET 请求的请求体是空字节串。

Python：

```python
import hashlib, hmac, json, time

body = json.dumps(payload, ensure_ascii=False).encode("utf-8")
ts = str(int(time.time()))
msg = f"{ts}\nPOST\n/open/v1/messages\n".encode() + body
sig = hmac.new(KEY.encode(), msg, hashlib.sha256).hexdigest()
headers = {"Content-Type": "application/json", "X-WF-Timestamp": ts, "X-WF-Signature": sig}
httpx.post(URL, content=body, headers=headers)
```

Node.js：

```js
const crypto = require("crypto");
const body = Buffer.from(JSON.stringify(payload), "utf8");
const ts = String(Math.floor(Date.now() / 1000));
const sig = crypto
  .createHmac("sha256", KEY)
  .update(Buffer.concat([Buffer.from(`${ts}\nPOST\n/open/v1/messages\n`), body]))
  .digest("hex");
await fetch(URL, {
  method: "POST",
  headers: { "Content-Type": "application/json", "X-WF-Timestamp": ts, "X-WF-Signature": sig },
  body,
});
```

两台电脑的时钟要同步（Windows「设置 → 时间 → 立即同步」）。`/open/v1/ping` 会返回服务器时间，可以用它检查时钟差。

## 4. 接口

### `GET /open/v1/ping`

检查连通和签名。

```json
{ "ok": true, "version": "v1", "time": 1735660800, "queue": 0 }
```

### `POST /open/v1/messages`

批量推送消息，`Content-Type: application/json`。

```json
{
  "platform": "telegram",
  "messages": [
    {
      "id": "8812",
      "chat":   { "id": "-1001234567", "name": "Alpha 冲狗群", "avatar": "https://..." },
      "sender": { "id": "998877", "name": "Alice", "avatar": "https://..." },
      "time": 1735660800123,
      "type": "text",
      "text": "看下这个 0xbb4cdb9cbd36b01bd1cbaebf2de08d9173bc095c",
      "reply": { "senderId": "556", "senderName": "Bob", "text": "被回复的那句话" },
      "link":  { "url": "https://...", "title": "链接标题" },
      "image": "https://...",
      "isSelf": false
    }
  ]
}
```

#### 顶层字段

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `platform` | 是 | 平台标识，2–16 位，小写字母开头，只能用 `a-z 0-9 _ -`。同一个平台始终用同一个值。已知的值会显示对应角标：`telegram`、`discord`、`qq`、`slack`、`whatsapp`、`line`、`x`、`dingtalk`、`feishu`、`lark`、`wecom`、`matrix`、`signal`、`kook`。其他值显示前两个字母。 |
| `messages` | 是 | 1–100 条消息 |

#### 消息字段

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `id` | 是 | 消息在该**群**内的唯一 ID，字符串或整数。**这是去重键**，重试时必须用同一个 ID。 |
| `chat.id` | 是 | 群 ID |
| `chat.name` | 否 | 群名，最多 80 字。为空时沿用上次推送的名字。 |
| `chat.avatar` | 否 | 群头像地址，见第 6 节 |
| `sender.id` | 是 | 发言人 ID。星标、屏蔽、备注、喊单战绩都按它区分，要用平台里**不会变**的 ID，不要用昵称。 |
| `sender.name` | 否 | 发言人显示名，最多 64 字 |
| `sender.avatar` | 否 | 发言人头像地址 |
| `time` | 否 | 发送时间，毫秒或秒都可以，超过 10 位数字按毫秒算。缺省时用收到的时间。 |
| `type` | 否 | `text`（默认）、`image`、`sticker`、`video`、`voice`、`file`、`link` |
| `text` | 视情况 | 正文，最多 2000 字，超出截断。合约地址和 `$TICKER` 会从这里识别。 |
| `image` | 否 | 图片地址。有图片时，`text` 可以留空或填配图文字。 |
| `link.url` / `link.title` | 否 | 链接卡片。`type=link` 且没有 `text` 时，正文显示为「标题 + 地址」。 |
| `reply.senderId` / `reply.senderName` / `reply.text` | 否 | 被回复的那条消息，显示成引用块（`text` 最多 500 字） |
| `isSelf` | 否 | 是不是推送账号自己发的。自己发的消息不响提示音。 |

`text`、`image`、`link` 至少要有一项。`id`、`chat.id`、`sender.id`、`reply.senderId` 只能用 `A-Z a-z 0-9 _ . = + -`，最长 64 位。如果平台的 ID 里有别的字符（比如 Matrix 的 `!abc:server`），请先做 base64url 或哈希再传，**并且每次都用同样的转换**。

#### 返回

HTTP 200，逐条给出结果：

```json
{
  "ok": true,
  "platform": "telegram",
  "accepted": 1, "duplicate": 0, "ignored": 1, "rejected": 1,
  "queue": 1,
  "results": [
    { "id": "8812", "status": "accepted" },
    { "id": "8813", "status": "ignored", "reason": "这个群还没在「群聊选择管理」里加入监控" },
    { "id": "8814", "status": "rejected", "reason": "time 早于 30 天，信息流不再保留" }
  ]
}
```

| status | 含义 | 推送端怎么处理 |
| --- | --- | --- |
| `accepted` | 已进接收队列，通常 1 秒内出现在信息流里 | 完成 |
| `duplicate` | 这个 ID 已经收过了 | 当成功处理 |
| `ignored` | 群没加入监控，消息丢弃，但群和发言人会记进目录 | 不用重试。加入监控后只收**之后**推送的消息 |
| `rejected` | 字段不合法，`reason` 写了原因 | 修数据，不要原样重试 |

#### 错误码

| HTTP | 原因 | 重试 |
| --- | --- | --- |
| 400 | 请求体不是 JSON，或 `platform` / `messages` 不合法 | 否 |
| 401 | 缺签名头、签名不对、时间戳超出 ±300 秒 | 校准时钟或密钥后再试 |
| 403 | 来源 IP 不在白名单，或带了浏览器 `Origin` 头 | 否 |
| 404 | 路径不对（局域网端口上只有 `/open/v1/*`） | 否 |
| 413 | 超过 100 条或 512 KB | 拆小批次 |
| 415 | `Content-Type` 不是 `application/json` | 否 |
| 429 | 限流、队列已满，或签名错太多被临时封禁 | 按 `Retry-After` 等待后重试 |
| 503 | 开放接口没开或没有密钥 | 在本机开启 |

## 5. 排序、去重与可靠性

- **排序**按 `time`（发送时间），不按到达时间。晚到的消息会插到信息流里对应的时间位置，不会顶到最上面。
- **时间纠正**：`time` 比服务器时间晚 5 秒以上的，按收到时间算，避免消息一直钉在顶部；早于 30 天的拒收，因为信息流只保留 30 天。
- **提示音**：沿用现有规则，超过 2 分钟的旧消息不响。补推历史消息不会响成一片。
- **队列**：通过校验的消息进内存队列（上限 2000 条），由单个协程按时间顺序写库。队列满了整批返回 429，这批消息一条都不会入队。
- **可靠性**：返回 200 之后、写库之前如果服务重启，队列里的消息会丢。推送端要保证**至少一次**投递：没拿到 200 就用**同样的 `id`** 重试，服务端会按 `平台:群:id` 去重。示例脚本里的 `push()` 已经这样实现。
- **建议批量**：实时消息逐条推或攒 0.5 秒一批都可以；补历史时每批 100 条，批次之间间隔 100 ms 以上。
- **不支持**编辑和撤回。同一个 `id` 再推一次会被当成重复消息。

## 6. 头像与图片（接收端缓存）

推送端只给地址（`chat.avatar`、`sender.avatar`、`image`），本服务在页面第一次需要时下载，并缓存到本机 `data/open_media/`：

- 浏览器只访问 `127.0.0.1:8765`，**不会**直连对方平台的 CDN。所以 Telegram 这类地址里带 bot token 的文件链接，也不会暴露给网页。
- 头像：地址不变时缓存 3 天。地址变了（换头像，或签名地址过期）会重新下载，但同一个人最多每小时下载一次。下载失败时继续用旧图。头像地址可以每条都带，也可以只在变化时带；为空时保留上次的地址。
- 图片：页面第一次显示时现场下载，之后读缓存，按地址缓存 30 天。下载失败后 10 分钟内不再重试。
- 限制：只接受 http / https；头像最大 2 MB，图片最大 8 MB；只认 png / jpg / gif / webp（按文件头判断，不看扩展名）；最多跟随 4 次跳转。
- 地址可以指向公网，也可以指向**局域网**里的机器（比如推送端自己起一个文件服务）；指向本机回环（`127.0.0.1`）、链路本地（`169.254.*`）和保留地址的会被拒绝。
- 下载不走系统代理。如果本机直连不了对方 CDN（例如国内网络下的 Telegram / Discord 图片），请推送端先把图片转存到局域网能访问的地址，再把那个地址填进来。
- 下载不走系统代理。如果本机直连不了对方 CDN（例如国内网络下的 Telegram / Discord 图片），请推送端先把图片转存到局域网能访问的地址，再把那个地址填进来。
- 地址需要能直接 GET 下载，不能依赖 Cookie 或额外的请求头。Discord 这类会过期的签名地址也可以用，过期后下一条消息带上新地址即可。

## 7. 在信息流里怎么显示

- 群名胶囊前面有平台角标（`TG`、`DC`、`QQ`…），颜色按平台区分。不同平台的同名群一眼就能分开。
- 卡片的其他部分和微信消息一样：头像、昵称备注、星标、「不看此人 / 此群」、引用块、图片、合约卡片、喊单人战绩、复制、K 线。
- 同一个人在同一个群 5 分钟内的连续发言照常合并。人和群的 ID 都带平台前缀，所以不同平台不会合并。
- 「群聊选择管理」里，推送过的群和微信群列在一起（「读取本机群」，名字前带 `[Telegram]` 之类的标记）。勾选「全部消息 / 只看 CA」、群备注、成员列表（成员是推送过消息的人）、只听部分人，用法都和微信群一样。
- 星标、屏蔽、备注、CA 榜的用户 ID 形如 `telegram:998877`。

## 8. 接入清单

1. 本机：「开放接口」页生成密钥 → 开启 → 放行防火墙 → 记下推送地址。
2. 推送端：配置推送地址和密钥，跑示例脚本 `ping` 通过。
3. 推送端：从平台收到群消息后，按第 4 节组装字段，`chat.id`、`sender.id` 用平台的稳定 ID。
4. 推一条消息，到「开放接口」页的「推送过的群」里点「加入监控」。
5. 再推一条消息，确认出现在本地页，群名前有平台角标。
6. 推送端实现重试：没拿到 200 就用同样的 `id` 重试，401 先检查时钟。
7. 可选：在「开放接口」页填 IP 白名单，只放行推送端那台机器。

## 9. 排查

| 现象 | 检查 |
| --- | --- |
| 连接超时或被拒绝 | 「开放接口」页是否显示「监听中」；防火墙规则；推送地址用的是不是本机的局域网 IP；两台机器是否在同一网段 |
| 401 签名不正确 | 签名用的字节和发出的请求体是否一致；路径是否是 `/open/v1/messages`；密钥是否是最新生成的那把 |
| 401 时间戳超出 | 两台机器的时钟差，用 `ping` 返回的 `time` 对比 |
| 403 | 推送端 IP 不在白名单；或者推送端跑在浏览器里（不支持） |
| 全部 `ignored` | 群还没加入监控 |
| 消息到了但看不见 | 「群聊选择管理」里「全部消息 / 只看 CA」是否勾了这个群；这个群或这个人是否被屏蔽 |
| 头像或图片不显示 | 用推送端机器直接打开地址试试；地址是否要求登录；是否超过大小限制。服务日志里会有「开放接口图片不可用」和原因（不记录地址） |

服务日志（`wechat-feed.cmd logs`）只记录来源 IP、条数和结果，不记录消息正文和图片地址。
